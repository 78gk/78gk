# Claude for OSS Fast-Track (7 Days)

This is a one-week execution plan to maximize acceptance odds for **Claude for OSS** using rapid, visible open-source momentum.

## Day 0 (Today): Apply Immediately

- Submit your application now with measurable impact and concrete next-week execution.
- Use `APPLICATION_TEXT_CLAUDE_OSS.md`.
- Include:
  - flagship repo link
  - current metrics
  - this week’s contributor/roadmap commitments

## Day 1: Pick a Flagship Repo + Tighten Entry Point

- Choose one repo as the OSS focus for the week.
- Ensure the repo has:
  - clear problem statement
  - fast quickstart
  - clear roadmap
  - contribution process
- Add at least 3 scoped issues tagged `good first issue` or `help wanted`.

## Day 2: Make Contributing Frictionless

- Add issue templates and contribution guidelines.
- Publish concrete “first contribution” tasks with acceptance criteria.
- Keep issue scope small enough for <2 hours each.

## Day 3: Start External Contributor Push

- Share targeted outreach messages in communities and peer networks.
- Invite contributors to specific issues, not a general ask.
- Track responses and interested contributors in one place.

## Day 4: Merge External PRs Fast

- Review incoming PRs quickly (target under 24h).
- Give actionable feedback fast.
- Merge qualifying PRs and thank contributors publicly.

## Day 5: Publish Reusable Artifact

- Ship one reusable module/package/template from your flagship repo.
- Add short usage docs and an example.
- Announce release with clear “why this helps developers” framing.

## Day 6: Collect Proof

- Gather links for:
  - merged external PRs
  - unique contributors
  - issues opened/closed
  - release/package/docs
  - community discussions/posts
- Prepare follow-up update with concise metrics.

## Day 7: Send Follow-Up

- If application flow allows, send your one-week evidence update.
- If no response yet, send a concise support follow-up with links and outcomes.

---

## Daily Operating Rules

- Keep reviewer response time under 24h.
- Prioritize merges and contributor support over new features.
- Every day should produce at least one visible OSS signal (issue, PR, release, or guide).

---

## End-of-Week Evidence Checklist

- [ ] Applied with a special-case impact narrative
- [ ] Selected one flagship repo and focused all activity there
- [ ] Added/updated contribution docs and issue templates
- [ ] Opened multiple scoped contributor issues
- [ ] Merged external PRs
- [ ] Published at least one reusable artifact/module
- [ ] Sent acceptance follow-up with evidence links
