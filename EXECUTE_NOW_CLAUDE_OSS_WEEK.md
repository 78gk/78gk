## Step 2 (Now, 30 minutes): Open 5 Issues in Flagship Repo

Create these in `https://github.com/78gk/Sales-Agent-Evaluation-Bench/issues/new/choose`.

### Issue 1
- Title: `[good first issue] Add 5-minute Quickstart section for local benchmark run`
- Labels: `good first issue`
- Body:
  - Task summary: Add a concise quickstart with exact prerequisites and one working command path.
  - Context: New contributors need instant local success before deeper contributions.
  - Acceptance criteria:
    - [ ] README includes prerequisites section
    - [ ] README includes first-run commands
    - [ ] README includes expected output/success criteria
    - [ ] Verified commands are accurate

### Issue 2
- Title: `[good first issue] Add benchmark results interpretation guide`
- Labels: `good first issue`
- Body:
  - Task summary: Add a short section explaining how to interpret key benchmark metrics.
  - Context: Contributors should understand pass/fail and delta metrics consistently.
  - Acceptance criteria:
    - [ ] Defines each key metric in plain language
    - [ ] Explains one sample result interpretation
    - [ ] Linked from main README

### Issue 3
- Title: `[help wanted] Add reproducibility checklist for contributors`
- Labels: `help wanted`
- Body:
  - Scope: Contributor-facing reproducibility checklist
  - Problem: Different environments can produce confusion during setup and evaluation.
  - Definition of done:
    - [ ] Checklist covers env setup, seeds, dataset split handling
    - [ ] Checklist references exact files/commands
    - [ ] Added to CONTRIBUTING or docs

### Issue 4
- Title: `[help wanted] Add one minimal example for adding a new eval task`
- Labels: `help wanted`
- Body:
  - Scope: One end-to-end minimal “add task” example
  - Problem: New contributors need a clear pattern for extending benchmark tasks.
  - Definition of done:
    - [ ] Includes minimal example task
    - [ ] Documents where to register it
    - [ ] Documents how to run and validate it

### Issue 5
- Title: `[good first issue] Improve contributing section with PR workflow`
- Labels: `good first issue`
- Body:
  - Task summary: Improve contribution docs with branch naming, commit expectations, and PR checklist.
  - Context: Faster reviews need consistent PR quality.
  - Acceptance criteria:
    - [ ] Branch naming convention documented
    - [ ] PR checklist added
    - [ ] Links to issue-first workflow included
